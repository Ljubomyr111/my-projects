Find square root: exhaustive search
// x = 1000.0, epsilon = 0.01 
double squareRootExhaustive(double x, double epsilon) { 
   double step = epsilon * epsilon; 
   double ans = 0.0; 
   // Perform exhaustive search 
   while (fabs(ans * ans - x) >= epsilon && ans * ans <= x) { 
       ans += step; 
   } 
   // If the square of ans exceeds x, raise an error 
   if (ans * ans > x) { 
       printf("Error: No solution found, the current answer: %f\n", ans); 
       exit(1);  // Exiting with error code 
   } 
   printf("Answer: %f \n", ans); 
   return ans; 
}
Answer: 31.622700 

Exhaustive enumeration
● The algorithmic technique used in this program is a variant of guess and 
check called exhaustive enumeration. 
● We enumerate all* possibilities until we get to the right answer or exhaust the 
space of possibilities. 
● At first blush, this may seem like an incredibly stupid way to solve a problem. 
Surprisingly, however, exhaustive enumeration algorithms are often the most 
practical way to solve a problem. 
● They are typically easy to implement and easy to understand. And, in many 
cases, they run fast enough for all practical purposes.

double squareRootExhaustive_timer(double x, double epsilon) { 
   clock_t start_time = clock(); 
   double step = epsilon * epsilon; 
   double ans = 0.0; 
   // Perform exhaustive search 
   while (fabs(ans * ans - x) >= epsilon && ans * ans <= x) { 
       ans += step; 
   } 
   // If the square of ans exceeds x, raise an error 
   if (ans * ans > x) { 
       printf("Error: No solution found, the current answer: %f\n", ans); 
       exit(1);  // Exiting with error code 
   } 
   printf("Answer: %f \n", ans); 
   clock_t end_time = clock(); 
   printf("Function duration: %.5f seconds\n", (double)(end_time - start_time) / CLOCKS_PER_SEC); 
   return ans; 
}

Find square root: exhaustive search + count operations
// x= 1000.0, epsilon = 0.01 
double squareRootExhaustive_counts_operations(double x, double epsilon) { 
   double step = epsilon * epsilon; 
   double ans = 0.0; 
   int i = 0; 
   // Perform exhaustive search 
   while (fabs(ans * ans - x) >= epsilon && ans * ans <= x) { 
       ans += step; 
       ++i; 
   } 
   // If the square of ans exceeds x, raise an error 
   if (ans * ans > x) { 
       printf("Error: No solution found, the current answer: %f, iteration: %d\n", ans, i); 
       exit(1);  // Exiting with error code 
   } 
   printf("Answer: %f, 2+2*i+1: %d\n", ans, 2+2*i+1); 
   return ans; 
}
Answer: 31.622700, 2+2*i+1: 632457

Asymptotic notation
● We use something called asymptotic notation to provide a formal way to talk 
about the relationship between the running time of an algorithm and the size 
of its inputs. 
● The underlying motivation is that almost any algorithm is sufficiently efficient 
when run on small inputs. 
● What we typically need to worry about is the efficiency of the algorithm when 
run on very large inputs. 
● As a proxy for “very large,” asymptotic notation describes the complexity of an 
algorithm as the size of its inputs approaches infinity.

// Function to determine if array L1 is a subset of L2 
bool isSubset(int L1[], int size1, int L2[], int size2) { 
   for (int i = 0; i < size1; i++) { 
       bool matched = false;   
       for (int j = 0; j < size2; j++) 
           if (L1[i] == L2[j]) { 
               matched = true;   
               break;   
           } 
       
       if (!matched) return false; 
       
   } 
   return true; 
}

4. Using the new guess, repeat process until close enough

Bisection search
Bisection search is a method to find a value by repeatedly halving the search 
interval until the desired precision is reached.
Steps (to find squared root):
1. Start with a low and high bound.
2. Compute the midpoint: mid = (low + high)/2.
3. Check if mid is close enough to the target.
○ If yes → stop.
○ If no → decide which half to search next:
■ If mid² > x, search lower half.
■ If mid² < x, search upper half.
4. Repeat until the interval is small enough.

Other asymptotic notations 
1. Big-O Notation (O-notation) represents the upper bound complexity of an 
algorithm.
2. Omega Notation (Ω-notation) represents lower bound on the algorithm’s time 
complexity.
3. Theta Notation (Θ-notation) - average-case complexity of an algorithm.
